Fast mode (Pillow-AllSIMD)¶

Fast mode lets operations use kernels that are faster and whose results may differ from Pillow’s by small, documented amounts. It is on by default: the operations listed below use their fast kernels. The other operations, and every operation in exact mode (fast mode off), compute with Pillow’s arithmetic, or an integer form of it that rounds differently by one level at most in a few places (resize with 16-bit coefficients, RGB to L with 15-bit ones). Fast mode was off by default until October 2026.

This is a Pillow-AllSIMD feature: neither Pillow nor Pillow-SIMD has a fast mode. Check for it with features.check_feature("fast").

Turning it off¶

Set the PILLOW_ALLSIMD_FAST environment variable before PIL.Image is imported (PILLOW_SIMD_FAST, its former name, is read when PILLOW_ALLSIMD_FAST isn’t set). 0, false, off, no and an empty value turn fast mode off; 1, true, on and yes turn it on. Any other value gives a warning and leaves the setting unchanged:

PILLOW_ALLSIMD_FAST=0 python3 app.py

Or call set_fast(), or use the fast_mode context manager for one block:

from PIL import Image, ImageFilter, features

if features.check_feature("fast"):
    Image.set_fast(False)

with Image.fast_mode(False):
    blurred = im.filter(ImageFilter.GaussianBlur(2))

The setting is process-wide: it applies to every thread, including while a fast_mode() block runs. Each operation reads it once, when the operation starts, so a call never mixes exact and fast kernels.

What it guarantees¶

  • Exact when off. With fast mode off, the operations run the exact kernels, the same as before fast mode existed.

  • Deterministic. A fast kernel’s result depends only on its input and arguments, and is the same on every build and architecture of a given Pillow-AllSIMD version. (Large downscales use the exact resize and reduce kernels in another order, so they are as reproducible as those.)

  • Bounded. For each fast kernel, the largest difference from the exact result and its error against a float reference of the operation are documented below and checked by the tests.

  • Same shape. Output mode, size and edge handling are those of the exact operation; only pixel values differ.

  • Not stable across versions. A later release may change a fast kernel’s results when the kernel improves. The exact path follows Pillow.

Turn fast mode off if you compare pixels with reference images made by Pillow, or cache or deduplicate images by their content across versions.

Operations with a fast kernel¶

Speed-ups are for 2560x1600 RGB images on one core of an Intel Core Ultra 9 285H (AVX2) and an NVIDIA Jetson Orin (NEON).

Other operations, and other arguments of these, use the exact kernels in fast mode too.

Functions¶

PIL.Image.set_fast(enabled: bool = True) → None[source]

Lets operations use faster kernels whose results may differ from Pillow’s by small, documented amounts, or goes back to the exact kernels, which follow Pillow’s arithmetic. On by default; the PILLOW_ALLSIMD_FAST environment variable (or PILLOW_SIMD_FAST, its former name) sets it when PIL.Image is imported, so PILLOW_ALLSIMD_FAST=0 gives the exact kernels. The setting is process-wide, and each operation reads it once when it starts. The operations with a fast kernel, and how far their results may differ, are listed in Fast mode (Pillow-AllSIMD).

Check for the feature with features.check_feature("fast").

Parameters:

enabled – True for the fast kernels, False for the exact ones.

PIL.Image.get_fast() → bool[source]

Whether operations may use the fast kernels; see set_fast().

class PIL.Image.fast_mode(enabled: bool = True)[source]

Context manager that calls set_fast() on entry and restores the previous setting on exit, for example to use the exact kernels in one place:

with Image.fast_mode(False):
    im = im.filter(ImageFilter.GaussianBlur(2))

The setting is process-wide: it applies to every thread while the block runs.

Parameters:

enabled – The setting inside the block.
